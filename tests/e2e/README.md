# tests/e2e/ — 端到端测试

## 技术栈
pytest · httpx · Playwright（可选，用于前端）

## 职责
验证**完整业务链路**与**演示场景脚本**。这是演示前的最后一道保险。

## 放什么代码

| 文件 | 测什么 |
|---|---|
| `test_full_pipeline.py` | 造数 → 采集 → 建模 → 治理 → 特征 → 训练 → 评分 → ADS 全链路跑通 |
| `test_demo_scenario.py` | **按演示脚本完整走一遍**，验证每一步的数据都符合预期 |
| `test_order_delay_drilldown.py` | 从驾驶舱 → 高风险订单 → 缺料/设备/质量原因的下钻链路 |
| `test_ai_analysis.py` | 点亮「AI 分析」按钮，验证 SSE 流式返回完整且包含证据 |
| `test_reset_and_rerun.py` | 重置 → 重跑 → 结果一致（演示可重来性） |
| `test_disaster_recovery.py` | 模拟单表失败 → 重跑 → 数据一致 |

## 演示场景测试（最重要）

```
test_demo_scenario.py 断言清单：
  ✓ 驾驶舱各项指标均非空且合理（按期率在 0.5~1.0 之间）
  ✓ 存在至少 3 个高风险订单（否则延期风险页没东西可演示）
  ✓ 每个高风险订单都有归因（top_reason_1 非空）
  ✓ 存在至少 1 个缺料订单（否则齐套页没东西可演示）
  ✓ 存在至少 1 台异常设备（否则设备页没东西可演示）
  ✓ 治理看板有命中问题（否则治理演示没东西可展示）
  ✓ MCP 工具全部返回成功
  ✓ Agent 能在 60 秒内完成一次根因分析
```

**这个测试通过 = 演示不会翻车。** 演示前必须跑。

## 干什么事情
1. 演示前一天与当天早上各跑一次
2. 任一断言失败立即修复，**绝不带病上演示**
3. 测试输出生成"演示就绪报告"，列出各页面的预期数字，供演示人对照
4. 测试数据用固定种子生成，结果可复现，便于定位问题
