# transforms/models/staging/ — 标准化层

## 技术栈
dbt（SQL + Jinja2）· dbt_utils 宏包

## 职责
把 ODS 的"原样数据"变成"干净明细"。这是数据质量的**第一道闸门**。

## 放什么代码

| 文件 | 处理内容 |
|---|---|
| `stg_mdm_*.sql` | 主数据标准化：客户、产品、物料、设备、供应商、成本中心 |
| `stg_crm_*.sql` | CRM 客户与商机 |
| `stg_plm_*.sql` | 产品、BOM、工艺路线、工序 |
| `stg_srm_*.sql` | 供应商、采购订单、到货 |
| `stg_erp_*.sql` | 销售订单、生产订单、财务凭证、应收 |
| `stg_mes_*.sql` | 工单、报工、生产实绩 |
| `stg_wms_*.sql` | 库存、出入库流水 |
| `stg_qms_*.sql` | 检验、不合格品、返工 |
| `stg_eam_*.sql` | 设备、故障、维修、点检 |
| `stg_energy_*.sql` | 设备能耗、车间能耗 |

## 标准处理动作（每个 stg 模型都要做）

1. **编码归一**：把 9 套系统的不同编码风格（`CUST_ID` / `CUSTOMER_NO` / `客户编号`）收敛为统一键
2. **类型规整**：字符串日期 → `date`/`timestamp`，文本数字 → `numeric`，统一精度
3. **去重**：按业务主键 + `_row_hash` 保留最新版本
4. **空值处理**：空字符串 → `NULL`，`'-'` / `'N/A'` 等占位符统一
5. **审计列透传**：保留 `_batch_id` / `_extract_ts`，供血缘追溯

## 干什么事情
1. 统一都实现为**视图**（view），不物化，避免存储膨胀
2. 不做业务逻辑，不写死过滤条件——业务规则属于 warehouse 层
3. 每个模型顶部注释标注来源表与负责人，`dbt docs` 会读取展示
