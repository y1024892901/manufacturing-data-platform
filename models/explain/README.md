# models/explain/ — SHAP 归因与自然语言解释

## 技术栈
**SHAP**（TreeExplainer）· Python · Jinja2 模板

## 职责
把模型的"黑盒概率"翻译成业务方能听懂的"原因链"。**这是整个演示系统最能打动人的部分。**

## 放什么代码

| 文件 | 内容 |
|---|---|
| `shap_explainer.py` | 加载模型，构建 TreeExplainer，批量计算 SHAP 值 |
| `attributor.py` | 把 SHAP 值聚合到业务维度（缺料/设备/质量/交期） |
| `narrator.py` | 把归因结果翻译成中文自然语言 |
| `templates/` | 解释文案模板（按风险等级与主因类型） |

## 从数字到人话的转换

```
SHAP 原始输出：
  kitting_rate        = -0.42   （缺料严重，推高延期概率）
  downtime_hours      = -0.28   （停机时间长）
  remaining_days      = -0.11   （剩余工期紧）
  completion_rate     = -0.08

聚合到业务维度后：
  缺料因素贡献 41.5%（主要物料 M-2043 齐套率仅 32%）
  设备因素贡献 27.7%（EQ-07 近 7 天累计停机 18.5 小时）
  工期因素贡献 10.9%（距计划完工仅 6 天，剩余完工量 45%）

最终生成的自然语言：
  「该订单延期风险高（概率 78%）。主要原因：
    ① 关键物料 M-2043 齐套率仅 32%，缺口 1,200 件，采购预计到货晚于计划完工日 4 天；
    ② 设备 EQ-07 近 7 天累计停机 18.5 小时，直接影响本单的钻孔工序。
    建议：优先协调 M-2043 紧急采购，并将钻孔工序调整至 EQ-05 执行。」
```

## 自然语言生成方式（关键设计）

**优先使用模板引擎而非 LLM 生成**——归因文案必须**绝对准确**，模板可保证数字与结论严格一致。
LLM 仅用于在模板输出基础上做**润色与扩展建议**（失败时回退到模板原文）。

> 这个分工很重要：**数字准确靠模板，表达流畅靠 LLM。** 反过来会让 AI 编造原因，演示风险极高。
> `tests/unit/test_narrator.py` 会断言"文案中出现的所有数字必须来自输入数据"。

## 干什么事情
1. 批量计算所有订单的归因，写入 `ads_order_delay_risk` 的 `top_reason_*` 字段
2. 生成全局特征重要性报告（供管理后台展示"模型学到了什么"）
3. 为单订单生成完整解释文本，供报表「AI 分析」按钮与 MCP `get_order_risk` 工具调用
