# ai/agents/dbt_generator/ — AI 辅助数据开发

## 技术栈
Python · LLM 网关（`ai/llm`）· dbt · Jinja2 模板

## 职责
演示「**AI 加速数据开发**」：新增数据源时，让 LLM 根据字段中文名自动生成 dbt 模型初稿。

## 触发场景

在管理后台登记完新表的字段后，点「生成模型初稿」，系统执行：

```
① 读取元数据：表名 + 字段名 + 字段中文含义 + 类型
② 读取同域的已有 stg_ 模型作为风格示例（few-shot）
③ 调用 LLM 生成 stg_xxx.sql 初稿（含注释、类型转换、去重逻辑）
④ 生成对应的 schema.yml（含基础 dbt test 建议）
⑤ 展示 diff 供人工确认 → 确认后写入 transforms/ 目录
```

## 放什么代码

| 文件 | 内容 |
|---|---|
| `generator.py` | 生成主流程 |
| `context.py` | 收集上下文：元数据 + 同域示例模型 + 项目规范 |
| `review.py` | 生成结果的静态检查（SQL 语法、命名规范、是否引用了不存在的表/字段） |
| `apply.py` | 人工确认后写入文件并触发 `dbt compile` 验证 |

## 关键约束

| 约束 | 说明 |
|---|---|
| **AI 只出初稿** | 必须人工确认后入库，**绝不自动上线** |
| **必须通过编译** | 初稿要跑 `dbt compile` 通过才算有效，否则重试或报错 |
| **风格一致性** | 用同域已有模型做 few-shot，保证命名、注释、审计列透传等约定一致 |
| **可追溯** | 记录生成用的 model / prompt 版本 / 是否被人工修改 |

## 演示价值

现场演示：新增一个「售后管理」系统 → 后台登记 3 张表 → 点生成 →
**30 秒产出 3 个 stg 模型 + schema.yml** → 人工微调 → 跑通。

直观展示「系统覆盖从 9 类扩展到 10 类几乎零开发量」，这是原方案"工作量控制"章节
想要但没做到的效果。

## 干什么事情
1. 降低新增数据源的开发成本（对应原方案"新增系统主要增加数据与 SQL，不增加平台组件"）
2. 同时作为「AI 在数据工程中真实落地」的演示素材
3. 生成质量数据回流：记录 AI 初稿被修改的比例，作为 Prompt 优化的依据
