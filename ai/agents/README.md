# ai/agents/ — Agent 编排与根因分析

## 技术栈
Python · **Anthropic Agent SDK**（或自研工具调用循环）· MCP Client · FastAPI SSE 流式输出

## 职责
让 AI **自主地**从现象追到原因，并给出建议。这是演示的最终高光环节。

## 放什么代码

| 文件 | 内容 |
|---|---|
| `runner.py` | Agent 主循环：接收问题 → 选工具/Skill → 多轮调用 → 汇总输出 |
| `mcp_client.py` | MCP 客户端：连接 MCP Server，列工具、调工具 |
| `orchestrator.py` | 编排策略：简单问题直连工具，复杂问题走 Skill 配方 |
| `stream.py` | SSE 流式输出：把 Agent 的中间步骤实时推给前端 |
| `session.py` | 会话管理：多轮对话上下文、历史记录持久化 |
| `guardrails.py` | 护栏：禁止编造数据、强制引用证据、失败回退 |

## 三类 Agent 任务

| Agent | 触发 | 典型流程 |
|---|---|---|
| **根因分析 Agent** | 报表页「AI 分析」按钮 / 自由提问 | 识别高风险订单 → 查缺料 → 查停机 → 查质量 → 查血缘 → 生成原因链与建议 |
| **问数 Agent** | "本月按期率是多少" | 识别指标 → `query_metric` → 格式化输出（附口径与来源） |
| **治理 Agent** | "今天质量如何" | `get_dq_status` → 问题下钻 → 影响评估 → 建议 |

## 根因分析的完整编排（演示主线）

```
用户：本月高风险的 5 个订单，按缺料、设备、质量分类说明原因

Agent 自主编排：
  ① query_metric(order_delay_count, by risk_level)    → 确认高风险订单数
  ② get_order_risk(order_no=...)  ×5                  → 拿到 SHAP 归因与证据
  ③ query_metric(kitting_rate, by order)              → 佐证缺料原因
  ④ run_sql(设备停机与订单关联)                          → 佐证设备原因
  ⑤ lookup_glossary("齐套率")                          → 引用准确口径
  ⑥ 汇总生成分类原因报告 + 处置建议

输出（流式逐字返回）：
  本月高风险订单 5 张，原因分类如下：
  ▎缺料主导（3 张）
     SO-20260812 / PO-20260815 — 物料 M-2043 齐套率 32%，缺口 1,200 件，
     采购预计到货晚于计划完工日 4 天
     ...
  ▎设备主导（1 张）...
  ▎质量主导（1 张）...
  ────────────────
  数据来源：ads_order_delay_risk（模型 v20260917 / 口径见 metric_order_delivery）
```

## 护栏设计（演示安全的保障）

| 护栏 | 实现 |
|---|---|
| **禁止编造** | Prompt 强约束 + 输出后校验：所有数字必须在工具返回中出现过 |
| **强制引用** | 输出必须包含订单号/物料编码/设备编号等可核查的具体标识 |
| **低温度** | `temperature ≤ 0.2`，保证演示结果稳定可复现 |
| **超时熔断** | 单次分析超过 60 秒强制结束并返回已完成部分 |
| **失败回退** | LLM 不可用时，回退到「纯模板 + SQL 直查」的降级方案，**演示不中断** |
| **步数上限** | 最多 8 轮工具调用，防止死循环 |
| **只读保证** | Agent 只能通过 MCP 工具访问数据，**物理上无法写数据库** |

## 干什么事情
1. 作为 FastAPI 的一个端点（`POST /agent/analyze`）对外提供 SSE 流
2. 从 MCP Server 动态获取工具清单，**MCP 加工具后 Agent 自动可用，无需改代码**
3. 完整记录每次分析的思考链、工具调用、耗时，写入会话表供复盘
4. 支持"追问"：基于上一轮会话继续深入
