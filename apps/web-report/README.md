# apps/web-report/ — 自研报表前端（替代帆软）

## 技术栈
React 18 · TypeScript 5 · Vite 5 · **ECharts 5** · TanStack Query · TailwindCSS · shadcn/ui

## 职责
5 个分析页面，支持筛选、联动、下钻、导出，以及**一键 AI 分析**。

## 放什么代码 / 文件

```
apps/web-report/
├── src/
│   ├── pages/       5 个页面
│   ├── components/  图表、筛选器、指标卡、AI 分析面板
│   ├── api/         接口客户端
│   ├── store/       全局筛选状态（跨页面共享）
│   └── hooks/       数据获取、联动、下钻
├── public/
└── vite.config.ts
```

## 五个页面（与原方案对齐）

| 页面 | 核心指标与图表 | 下钻路径 |
|---|---|---|
| **经营管理驾驶舱** | 客户数、商机金额、商机转化率、订单数、收入、完工率、按期率、合格率、高风险订单数、月度趋势 | → 订单 / 财务 / 风险明细 |
| **生产订单执行分析** | 计划量、完工量、剩余量、工序进度、预计完成日期 | → 工单 → 报工记录 |
| **生产订单延期风险** | 风险概率、等级分布、预计延期天数、**原因分布（SHAP 归因）**、处置建议 | → 缺料 / 设备 / 质量原因 |
| **库存齐套与缺料分析** | 需求量、可用库存、缺口、齐套率、预计到料、缺料排行 | → 物料 → 供应商 → 受影响订单 |
| **设备与质量影响分析** | 停机次数与时长、不良率、返工量、健康评分、异常能耗 | → 设备 → 工序 → 关联订单 |

## 统一交互能力（对应原方案 8.1 节）

| 能力 | 实现 |
|---|---|
| **统一筛选** | 全局筛选状态提升到 store，月份/工厂/车间/订单/产品/风险等级跨页面保持 |
| **图表联动** | 点击图表元素 → 更新全局筛选 → 其他图表与明细同步刷新（TanStack Query 缓存失效驱动） |
| **下钻路径** | 统一围绕**生产订单**组织（`order_no` 是全页面的枢轴键） |
| **明细与导出** | 每个图表支持查看明细表格，支持 CSV 导出 |
| **口径说明** | 每个指标名旁有信息图标，悬停显示口径（数据来自 `/metrics` 的 `definition` 字段） |

## ★ 一键 AI 分析（帆软难以实现的能力）

延期风险页/驾驶舱中，每个高风险订单旁有「AI 分析」按钮：

```
点击 → POST /agent/analyze (SSE)
     → 侧边抽屉打开，Agent 的思考步骤与工具调用实时显示：
        ▸ 正在查询订单风险...（get_order_risk）
        ▸ 正在核对缺料明细...（query_metric: kitting_rate）
        ▸ 正在检查设备停机...（run_sql）
        ▸ 正在检索指标口径...（lookup_glossary）
     → 逐字流式输出原因链、证据与处置建议
     → 底部显示数据来源与口径
```

**为什么用抽屉而不是弹窗**：抽屉不遮挡主图表，用户可对照图表看分析；且可连续点多个订单。

## 干什么事情
1. 所有数据来自 `apps/api`，前端不直连数据库
2. 图表统一封装为组件，保证视觉与交互一致
3. 页面加载走缓存，翻页与筛选不重新请求全量
4. 支持深浅色主题（会议室投影以浅色为主）
