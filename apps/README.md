# apps/ — 应用服务与前端

## 技术栈
**后端** Python 3.11 + FastAPI + SQLModel + Pydantic + Alembic
**前端** React 18 + TypeScript + Vite + ECharts（报表） / antd（后台）

## 职责
把数仓与 AI 能力交付给最终用户：一套自研报表 + 一套管理后台。

## 放什么代码 / 文件

```
apps/
├── api/          FastAPI 统一网关（报表数据 + 元数据 + Agent 代理）
├── admin/        管理后台的元数据模型与业务逻辑
├── web-report/   自研报表前端（5 个分析页面）
└── web-admin/    管理后台前端（系统/表/字段/规则/指标配置）
```

## 四个模块的角色

| 模块 | 面向 | 端口 | 核心能力 |
|---|---|---|---|
| `api` | 全部 | 8000 | 统一数据出口、权限、审计、OpenAPI 文档 |
| `admin` | 管理员 | — | 元数据 CRUD、同步触发、质量查看、血缘查询 |
| `web-report` | 管理层 / 业务 | 5173 | 5 个分析页面 + 一键 AI 分析 |
| `web-admin` | 数据管理员 | 5174 | 配置各源系统、表、字段、规则、指标 |

## 为什么把报表与后台拆成两个前端

| 理由 | 说明 |
|---|---|
| 用户不同 | 报表给管理层看，后台给数据管理员用，导航结构完全不同 |
| 演示清晰 | 汇报时明确区分"业务价值面"与"平台能力面" |
| 独立演进 | 改后台配置不影响报表演示稳定性 |
| 共用基础 | 共享同一套 API 客户端与设计基础，无重复建设 |

## 干什么事情
1. `api` 是唯一的数据出口：前端不直连数据库，全部走 API（便于加权限与审计）
2. `admin` 的元数据库存于独立的 `platform_meta` 库，**与数仓物理隔离**
3. 全部接口自动生成 OpenAPI 文档，`/docs` 可直接演示
