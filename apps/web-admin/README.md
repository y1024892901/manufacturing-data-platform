# apps/web-admin/ — 管理后台前端

## 技术栈
React 18 · TypeScript · Vite · **antd 5**（表格/表单密集场景效率最高）· TanStack Query

## 职责
"维护各个系统的地方"——数据管理员配置源系统、表、字段、规则、指标的操作界面。

## 放什么代码 / 文件

```
apps/web-admin/
├── src/
│   ├── pages/       各功能页面
│   ├── components/  表格、表单、血缘图、连接测试器
│   ├── api/         管理接口客户端
│   └── layouts/     侧边导航与布局
```

## 功能页面

| 页面 | 主要操作 |
|---|---|
| **概览** | 系统数、表数、今日同步次数、质量通过率、待处理问题 |
| **系统管理** | 新增系统、编辑连接配置、**测试连接**、启用/停用 |
| **表管理** | 表清单、字段明细、同步策略、手动触发同步、查看 DDL |
| **字段映射** | 表格化编辑：源字段名 / 目标字段名 / **中文业务含义** / 类型 / 主键 / 敏感 / 范围 |
| **同步监控** | 任务状态、运行历史、行数波动图、失败重跑 |
| **规则管理** | 规则 CRUD、试运行（立即检测并预览命中数）、命中问题下钻 |
| **指标管理** | 指标口径编辑、表达式预览、变更历史 |
| **血缘查询** | 交互式血缘图，点击节点展开上下游，支持列级查看 |
| **质量看板** | 通过率趋势、问题分布、治理前后对比 |
| **模型管理** | 模型版本列表、评估指标、手动重训、版本对比 |
| **审计日志** | LLM 调用与 SQL 调用记录，支持筛选与导出 |
| **用户权限** | 用户、角色、权限分配 |

## 关键交互设计

| 交互 | 设计 | 原因 |
|---|---|---|
| **字段映射** | 用可编辑表格而非逐字段表单 | 一张表几十个字段逐个弹窗填会疯掉 |
| **连接测试** | 保存前先测通 | 避免配置错误导致同步失败 |
| **规则试运行** | 编辑规则后点「试运行」，立即看到命中行数与样例 | 确认后再保存，避免误阻断下游 |
| **血缘图** | 力导向图 + 可折叠上下游，节点按层着色 | ods/dwd/dws/ads 一眼可辨 |
| **同步触发** | 单表同步、按系统同步、全量重跑三档 | 避免误触全量 |
| **危险操作二次确认** | 删除系统、全量重跑需输入系统名确认 | 演示现场防误操作 |

## 干什么事情
1. 让非开发人员（FDE 人员）能独立完成数据接入配置
2. 字段中文含义在此录入 → 自动成为数据字典与 AI 的语义来源
3. 演示亮点：**现场新增一个系统与 3 张表，几分钟内跑通全链路**
4. 与 `web-report` 共用同一套 API 客户端，但使用 antd 适配表单密集型场景
