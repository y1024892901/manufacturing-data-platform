# source-data/ — 源系统模拟与造数

## 技术栈
Python 3.11 · Faker / Mimesis · numpy · PostgreSQL（多 database 模拟多系统）· 可选 pandas

## 职责
模拟 9 类制造业务系统的数据，**并故意注入符合真实场景的数据质量问题**。

> 关键认知：**坏数据是治理能力的演示素材。** 如果源数据全干净，40 条治理规则一条都触发不了，
> 治理看板将是一片空白。造数引擎的输出必须包含"可预期的错误"。

## 放什么代码 / 文件

```
source-data/
├── generators/      各业务系统的造数模块（按域拆分）
├── schema/          各源系统的建表 DDL
├── injectors/       坏数据注入器（可配置开关与注入比例）
├── seeds/           造数种子与配置（保证可复现）
└── generate.py      造数引擎入口
```

## 造数必须满足的业务约束

造数不是随机填充，必须遵守制造业的真实因果链，否则模型学到的全是噪声：

| 约束 | 说明 |
|---|---|
| BOM 完整性 | 父件需求量 = 子件用量 × 父件计划量，逐层展开 |
| 工序顺序 | 工序必须属于有效工艺路线，开工 ≤ 完工，前道完工 ≤ 后道开工 |
| 时间因果 | 销售订单 → 生产订单 → 工单 → 报工 → 检验 → 入库，严格时序 |
| 故障相关性 | 设备故障导致对应工序停机，进而影响订单进度 |
| 质量传导 | 不良率高 → 返工量上升 → 完工日期后延 |
| 库存守恒 | 期初 + 入库 − 出库 = 期末，不得为负 |
| 齐套逻辑 | 齐套率由 BOM 需求与可用库存实际计算得出，不可单独生成 |

## 坏数据注入器（演示核心）

| 注入器 | 模拟的真实问题 | 预期被哪条规则捕获 |
|---|---|---|
| `dup_voucher` | 重复财务凭证 | F01 凭证唯一性 |
| `unbalanced_entry` | 借贷不平 | F02 借贷平衡 |
| `bad_date_order` | 计划/开工/完工日期倒置 | P03 日期顺序 |
| `invalid_operation` | 工序不在工艺路线中 | P04 工序有效性 |
| `orphan_equipment` | 设备不在台账中 | E01 设备编码有效 |
| `overlapping_state` | 设备状态时段重叠 | E02 状态时间不重叠 |
| `missing_inspection` | 点检记录缺失 | E04 点检完整性 |
| `negative_energy` | 能耗负值/异常波动 | E05 能耗合理性 |

**注入比例可配置**（如 2%~5%），演示时可现场调高比例重新跑一遍，直观展示治理效果的"前后对比"。

## 干什么事情
1. `python generate.py --profile demo --seed 20260917` 生成全量源数据
2. 固定种子保证**每次生成结果一致**，演示可复现
3. 支持按系统、按时间范围、按数据量档位生成
4. 生成完成后输出「造数报告」：各表行数、注入的坏数据条数与位置清单（供演示时对照）
