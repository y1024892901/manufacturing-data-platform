# 十系统功能目录与代码实施边界

## 建设原则

本项目的实现范围由两条线共同构成：

1. **系统本职线（纵向）**：每个系统都必须具备其本来负责的数据、单据、台账、规则、查询、审批和审计能力；
2. **跨系统流程线（横向）**：系统本职模块通过事件、单据引用和主数据副本形成真实制造业务闭环。

因此，不能以“该系统已在订单流程中被调用”认定该系统已完成。例如：QMS 不只是接收 MES 的检验任务，还必须有检验标准、检验计划、缺陷库、不合格评审、CAPA 和质量报表。

## 所有系统统一的代码标准

每个系统模块均按以下结构实现；不得只建表或只提供一个演示接口：

```text
source-apps/<system>/
  domain/        状态机、枚举、领域规则
  entity/        单据、台账、配置实体
  repo/          数据访问与领域查询
  service/       业务动作、校验、事务边界
  controller/    独立维护 API
  workflow/      本系统审批策略与审批回调
  integration/   上下游事件、分发、幂等处理
  query/         列表、详情、台账、统计查询
```

每个核心单据至少具备：草稿/提交/审核或确认/关闭或作废、状态时间轴、操作审计、权限校验、分页查询、详情查看和导出接口。

## 系统本职完成的最低验收

每一个系统达到以下五项后，才称为“已实现”：

1. 至少 5 个本职模块具有实体、服务、接口和角色权限；
2. 至少 3 类核心单据可以从创建流转到关闭或作废；
3. 至少 1 个审批流程和 1 个异常处理闭环；
4. 至少 2 个向其他系统发送或消费的幂等业务事件；
5. 至少 1 页本系统运营查询或统计报表。
