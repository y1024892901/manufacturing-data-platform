# docs/ — 文档中心

## 技术栈
Markdown + Mermaid 图表（Git 原生渲染，无需额外工具链）

## 职责
沉淀全项目的**设计契约**。这里的内容是各层实现的唯一依据，代码与文档冲突时以本文档为准并立即修正文档。

## 放什么代码 / 文件

| 文件 | 内容 | 谁会读 |
|---|---|---|
| `architecture.md` | 总体架构、分层职责、组件交互 | 全员 |
| `data-flow.md` | 端到端数据流向（含每层行数变化、耗时） | 数据开发 |
| `data-dictionary.md` | **核心交付物**：每张表、每个字段的业务含义 | 全员 / 客户 |
| `metrics.md` | 指标口径定义（分子分母、过滤条件、更新频率） | 分析师 / AI |
| `governance-rules.md` | 治理规则清单（编号、表达式、严重级别、处理动作） | 数据治理 |
| `admin-console.md` | 后管系统功能规格（页面、操作、权限） | 后端 / 前端 |
| `api-spec.md` | 接口契约 | 前端 / AI |
| `mcp-tools.md` | MCP 工具契约（入参、出参、权限、审计） | AI 开发 |
| `skills-catalog.md` | Skill 清单与触发条件 | AI 开发 |
| `demo-script.md` | 演示脚本（分钟级时间轴、话术、兜底方案） | 演示人 |
| `deployment.md` | 部署与故障恢复手册 | 运维 |

## 干什么事情
1. 在写第一行代码前，先在此冻结数据字典与指标口径
2. 每次模型/接口变更，先改文档再改代码
3. 演示前按 `demo-script.md` 完整彩排三遍，标注每步的兜底路径
