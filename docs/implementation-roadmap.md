# 制造业十系统演示平台：分阶段实施基线

## 目标

建设十个可独立维护、可按角色操作、可通过真实业务事件发生数据流转的系统：MDM、CRM、ERP、PLM、SRM、WMS、MES、QMS、EAM、能源管理。

本项目不复制商业套件的全部菜单；每个系统以“主数据/业务单据/审批控制/异常处置/上下游事件”五类能力作为完成标准。

十个系统各自必须实现的本职模块、单据及代码分层，见 [system-functional-catalog.md](system-functional-catalog.md)。该功能目录是范围基线；跨系统流程仅用于验证这些模块之间的联动，不能替代系统本职能力。

## 统一业务主线

```text
PLM 产品与工程变更
  -> MDM 主数据审批、发布与分发
  -> CRM 商机、报价、合同、销售订单
  -> ERP 信用、承诺交期、MRP、生产订单与财务
  -> SRM 采购、ASN、供应商交付
  -> WMS 收货、质检待检、上架、领料与库存
  -> MES 派工、开工、报工、返工与完工
  -> QMS 检验、不合格、处置、CAPA
  -> EAM 故障、停机、维修与备件
  -> 能源 计量、分摊、异常与成本
  -> 数仓、治理、风险分析、AI
```

## 交付顺序与验收门槛

> **实际进度不等同于阶段顺序**：项目按「每个系统纵向切片」推进，而非逐阶段串行完成。
> 当前 P1 主线已闭环，P2/P3/P4 各系统均有推进但完成度不一，P5 部分具备，P6/P7 未启动。
> 各系统逐项差距见 [current-status.md](current-status.md)。

### P0：工程基线与演示安全

- 技术文档统一为 MySQL 8 + Java 17 + Python；不再描述 PostgreSQL/pgvector/dbt-postgres 为当前实现。
- 维护一键演示重置：清空演示业务数据、加载固定种子、验证预期订单/缺料/设备故障/质量问题。
- 所有业务操作保留审计记录；演示账号只使用 `Test@123456`，生产口令不进入代码库。

**验收：** 文档、配置、运行环境的技术口径一致；演示可重复重置。

### P1：产品工程与主数据闭环

涉及：MDM、PLM、审批中心、ERP/MES/PLM 主数据副本。

1. 产品、物料、分类、单位、工作中心、工艺路线、BOM 的真实 CRUD；
2. EBOM -> MBOM 转换，BOM 行维护替代料、损耗率、生效/失效日期；
3. ECR/ECO 变更申请，工艺主管 -> 生产主管 -> 成本会计审批；
4. 发布后写入分发事件，分别向 ERP、MES、PLM 发送幂等分发任务；
5. BOM 变更影响分析：查询受影响产品、生产订单和物料需求。

**验收：** 不使用 `DemoController` 的虚拟单据；从真实 BOM 页面/API创建并审批，审批通过后 ERP/MES/PLM 均可查询新版本。

### P2：市场到订单、订单到计划

涉及：CRM、ERP、财务与审批中心。

- CRM：线索、商机、报价、合同、订单转化、销售预测；
- ERP：销售订单、信用检查、ATP、生产订单、MRP 建议、应收、回款、成本归集；
- 审批：折扣、信用例外、改单/取消单、订单下达。

**验收：** 一张 CRM 商机可转 ERP 销售订单，并生成可执行的生产与采购需求。

### P3：采购、仓储、质量闭环

涉及：SRM、WMS、QMS、ERP。

- SRM：供应商准入、询报价、定标、采购订单、ASN、绩效；
- WMS：收货、待检、上架、冻结、领料、退料、盘点、发货；
- QMS：来料/过程/完工检验、不合格、隔离、返工、退供、CAPA；
- 审批：采购金额、供应商准入、盘盈盘亏、让步接收、CAPA关闭。

**验收：** ASN 收货自动生成待检库存；QMS 结果驱动可用、隔离或退供库存。

### P4：生产执行、设备与能源闭环

涉及：MES、EAM、能源管理、WMS、QMS、ERP。

- MES：工单、派工、开工、报工、工序转移、返工、完工、Andon；
- EAM：设备树、点检、保养、故障、维修、停机、备件；
- 能源：仪表采集、设备/车间/订单能耗、定额、异常、分摊；
- 审批：返工、报废、重大故障、超额能耗处理。

**验收：** 设备故障可以影响具体工序和订单；返工、缺料、停机均影响订单预计交期。

### P5：十系统门户与运营管理界面

- 单点登录、系统门户、角色化工作台、统一待办、审批时间轴；
- 十个系统各自的核心维护页面；
- 跨系统数据流动地图、分发监控、异常待办、审计查询。

**验收：** 管理者和各岗位可从页面完成核心操作，不依赖 Swagger 或脚本。

### P6：造数、采集、数仓与治理

- 固定种子造数、坏数据注入、源系统增量采集；
- ODS -> DWD -> DWS -> ADS；
- 三域指标、跨层对账、质量规则、血缘和问题闭环。

**验收：** 订单、供应、设备、质量、财务可在 ADS 层按统一口径关联分析。

### P7：报表、AI、MCP 与 Skill

- 自研看板、订单风险页、库存齐套页、设备质量页、治理页；
- DeepSeek/千问、MCP 安全工具、Agent、可复用分析 Skill；
- AI 仅访问受控指标、ADS 数据和血缘；所有调用可审计。

**验收：** AI 能对高风险订单给出可核查的缺料、质量、设备、交期证据链和处置建议。

## 当前禁止事项

1. 在 P6 前不接入真实 AI 问数或延期模型；
2. 在 P5 前不以截图或 Swagger 代替十系统界面；
4. 不允许业务系统自行维护已由 MDM 发布的客户、供应商、物料、BOM 和工艺主数据。
