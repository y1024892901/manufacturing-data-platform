# ops/ — 运维与演示

> **整体计划** · 基础设施/运维（非十系统之一）

## 职责边界

让系统**可启动、可巡检、可恢复、可演示** —— 但在当前阶段，"可演示"已落地为三个端到端**验证脚本**，其余三项仍是规划。

| 负责 | 现状 |
|---|---|
| **可演示** | ✅ 3 个 Python 脚本，用真实 HTTP 调用把关键业务链路跑一遍并打印结果 |
| 可启动 | ❌ `start.sh` 未实现（当前靠 `infra/mysql8/start-mysql8.bat` + `mvn spring-boot:run`） |
| 可巡检 | ❌ 未实现 |
| 可恢复 | ❌ `reset.sh` / 备份未实现 |

**谁依赖它：**

| 依赖方 | 依赖什么 |
|---|---|
| 演示者 | 一条命令走通「主数据全生命周期」「BOM 三级审批」「审批边界」三条叙事线 |
| 开发自测 | 不需要前端界面即可验证后端审批引擎与分发逻辑是否正确 |
| 验收/回归 | 11 项断言式检查（`demo_approval_boundary.py`）可作为轻量回归用例 |

## 不做什么

- **不替代单元测试** —— 这些脚本打的是**运行中的真实服务**（`localhost:8080`），不是 mock；它们是演示与冒烟验证，不是 CI 测试套件。
- **不造数据** —— 建物料/提单据只是演示叙事的必要步骤，批量造数归造数引擎。
- **不碰数据库结构** —— 建库建表归 `infra/db-init/`；`demo_master_data_lifecycle.py` 只是**只读查询**副本表做验证。
- **不引入第三方依赖** —— 已实现的脚本全部只用 Python 标准库，`python xxx.py` 即可运行，无需 `pip install`。
- **不做生产运维** —— 无监控告警、无备份策略、无权限收敛；定位是单机演示环境。

### 三条规划原则

1. **演示脚本必须可重复运行** —— 每次运行用唯一编码（`M-<月日时分秒>`）或先清理旧数据，绝不做「跑第二次就报错」的脚本。
2. **脚本输出即演示台词** —— 用 `=` 分隔线分段、关键对比处打 `★`，输出可直接投屏讲解。
3. **零依赖、零配置** —— 只用标准库 + 命令行直接运行；口令等配置应来自 `infra/.env` 而非写死在脚本里（**当前有 1 处未达标，见 [STATUS.md](STATUS.md)**）。
