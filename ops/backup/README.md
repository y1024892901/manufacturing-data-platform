# ops/backup/ — 备份与恢复

## 技术栈
`pg_dump` / `pg_restore` · Docker volume 快照 · Bash

## 放什么代码

| 文件 | 用途 |
|---|---|
| `snapshot.sh` | 导出全部数据库快照到 `data/snapshots/` |
| `restore.sh` | 从快照恢复（指定快照名） |
| `list_snapshots.sh` | 列出可用快照与元信息 |
| `volume_backup.sh` | Docker volume 级备份 |

## 快照使用场景

| 场景 | 何时用 |
|---|---|
| **演示前定型** | 数据调好后拍快照，演示当天直接恢复，不重跑链路 |
| **演示中翻车** | 现场数据被搞乱，30 秒恢复到干净状态 |
| **版本对比** | 保留不同配置下的数据快照，对比治理效果 |

## 快照元信息

每次快照记录 `snapshot.json`：

| 字段 | 说明 |
|---|---|
| `name` | 快照名（时间戳 + 标签） |
| `created_at` | 创建时间 |
| `row_counts` | 各层表行数（便于恢复后校验） |
| `dq_pass_rate` | 当时的质量通过率 |
| `git_commit` | 代码版本（保证数据与代码匹配） |
| `note` | 备注（如"演示定型版"） |

## 干什么事情
1. **演示系统的最强保险**——任何不可恢复的问题，恢复快照即可
2. 快照包含元数据库，恢复后管理后台配置也一并还原
3. 定期演练恢复流程，确保真出事时能用
4. 快照文件不进 Git（体积大），但元信息 JSON 进 Git 便于追溯
