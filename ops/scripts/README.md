# ops/scripts/ — 运维脚本

## 技术栈
Bash（Git Bash 兼容）· PowerShell（Windows 原生）· Docker CLI · psql

## 放什么代码

| 脚本 | 用途 |
|---|---|
| `start.sh` | 启动全栈 + 等待健康检查通过 + 打印访问地址 |
| `stop.sh` | 优雅停止（保留数据卷） |
| `reset.sh` | **清空数据卷 + 重建 + 重新造数**（演示前必用） |
| `restart_service.sh` | 重启单个服务（演示中出问题时的快速恢复） |
| `demo_prep.sh` | 演示前完整准备流程 + 就绪检查清单 |
| `health_check.sh` | 巡检：服务状态、数据新鲜度、质量通过率 |
| `run_pipeline.sh` | 手动触发全链路（绕过调度） |
| `rerun_table.sh` | 单表重跑（故障恢复演示） |
| `export_results.sh` | 导出演示结果（CSV / 截图用的数据） |
| `check_env.sh` | 检查宿主机环境（Docker、端口占用、内存） |

## 关键脚本说明

### `demo_prep.sh` —— 演示前的救命脚本

执行顺序：

```
① 检查 Docker 与端口
② 重置数据库（清空 + 重建 schema）
③ 生成源数据（含坏数据注入）
④ 执行采集 → 建模 → 治理 → 特征 → 训练 → 评分
⑤ 同步语义层与血缘
⑥ 校验各层行数与质量通过率
⑦ 打印「演示就绪」检查清单（含各页面 URL 与预期数字）
```

**演示当天提前 30 分钟跑一次，任何环境问题都能提前发现。**

### `health_check.sh` —— 巡检项

| 检查项 | 期望 |
|---|---|
| 各容器状态 | 全部 `healthy` |
| 数据库连通 | 可连接且响应 < 100ms |
| 数据新鲜度 | ODS 最近批次在 24 小时内 |
| 质量通过率 | 不低于设定阈值 |
| 磁盘占用 | 低于 80% |
| **LLM API 连通** | 可正常调用（演示前必查） |

## 干什么事情
1. 所有脚本**幂等**，可重复执行
2. 脚本开头检查前置条件，失败时给出明确的人话提示
3. Windows 环境同时提供 `.ps1` 版本
4. 演示脚本支持 `--dry-run` 预览将要执行的操作
