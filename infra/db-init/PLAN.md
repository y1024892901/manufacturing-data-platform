# infra/db-init/ — 数据库初始化

> **整体计划** · 基础设施/运维（非十系统之一）

## 职责边界

用**一串按编号顺序执行的纯 SQL 脚本**，把一台空白的 MySQL 8.0.43 变成一台「打开 Navicat 就能看懂全部业务」的演示库。

它负责：

| 负责 | 产物 |
|---|---|
| 建库 | 18 个 database，分源系统层 / 数仓四层 / 平台层 |
| 建表 | 99 张表（主数据、业务系统、数仓框架、平台能力） |
| 建数据 | 组织、账号、角色、权限、审批链、治理规则、指标口径 |
| 建约定 | 状态机、主数据只读副本带 `master_version`、表名前缀规范、审计列约定 |

**谁依赖它：**

| 依赖方 | 依赖什么 |
|---|---|
| `source-apps/`（10 个 Java 系统） | `src_mdm` 的 16 张主数据表 + 各业务库的 `*_md_*` 只读副本表结构 |
| `apps/api`、MCP Server | `mfg_auth`（鉴权）、`mfg_app`（向量/会话）、`mfg_dws.metric_definition`（指标口径） |
| `orchestration/`、`transforms/` | `mfg_ods` / `mfg_dwd` / `mfg_dws` / `mfg_ads` 四层框架表 |
| `ops/` 三个演示脚本 | 36 个演示账号（统一口令 `Test@123456`）、7 条审批链、可分发的主数据 |

## 不做什么

- **不做增量迁移** —— 不是 Flyway/Liquibase，没有版本表、没有回滚脚本；脚本是「幂等重建」而非「版本演进」。改结构就地改脚本。
- **不建业务大表** —— DWD/DWS/ADS 的建模表由 `dw_kit` / dbt 按模型定义生成，本目录只建**框架性结构**（审计列约定、治理结果表、指标口径表）。
- **不造业务流水** —— 造数由造数引擎负责，本目录只播种「配置类 + 演示必需」的种子数据。
- **不管理实例启停** —— 那是 `infra/mysql8/` 的事。

### 三条脚本编写规范

1. **幂等第一** —— 建库建表一律 `IF NOT EXISTS`；种子数据用 `ON DUPLICATE KEY UPDATE`；配置表可 `DELETE` 后重建。任何脚本都能重复执行而不报错、不产生重复行。
2. **一个编号一个主题，不拆不并** —— `04` 与 `05` 是「业务系统上下集」而非两个阶段；`10`/`11` 是后补脚本，编号即顺序，**新脚本一律追加在末尾**。
3. **脚本自带验证输出** —— 每个脚本尾部用 `SELECT` 打印建成的库/表清单，执行时肉眼即可确认结果。
