# infra/mysql8/ — 本机 MySQL 8 实例管理

> **整体计划** · 基础设施/运维（非十系统之一）

## 职责边界

管理**本项目专用的 MySQL 8.0.43 独立实例**（`D:\mysql8`，端口 3306）：把它拉起来、看清楚它活着、优雅地关掉。

| 负责 | 说明 |
|---|---|
| 实例启停 | 3 个 Windows 批处理脚本，演示前一键拉起、收工一键关闭 |
| 端口冲突守卫 | 启动前主动检测本机原有 MySQL 5.7 服务是否抢占 3306，抢占则明确报错而非静默失败 |
| 状态可观测 | 一条命令看到「5.7 服务状态 + 8.0 监听状态 + 8.0 的版本/字符集/全部库列表」 |
| 口令隔离 | 关停与状态查询从 `infra/.env` 读 `MYSQL_PASSWORD`，脚本内不出现明文 |

**谁依赖它：**

| 依赖方 | 依赖什么 |
|---|---|
| `infra/db-init/` | 建库建表必须跑在这个实例上（**不能用 5.7**） |
| `source-apps/`（10 个 Java 系统） | 全部数据落在 3306 |
| `apps/api`、MCP Server、`ops/` 演示脚本 | 连接 `127.0.0.1:3306` |

## 不做什么

- **不装成 Windows 服务** —— 以进程方式运行，避免开机自启与原有 5.7 服务抢端口；也避免污染系统服务列表。
- **不动本机原有的 MySQL 5.7** —— `D:\mysql-5.7.32` 及其 18 个库（`book_store` 等）不属于本项目，脚本只**检测**它，绝不修改它。
- **不做安装器** —— 已安装完毕；README 中的建立过程仅作为换机复现参考，不是可重复执行的安装脚本。
- **不管数据库内容** —— 建库建表归 `db-init/`。
- **不做备份** —— 归 `ops/backup/`（尚未实现）。

## 规划内容

| 文件 | 定位 | 状态 |
|---|---|---|
| `start-mysql8.bat` | 启动实例，含 5.7 抢端口守卫与 20 秒就绪轮询 | ✅ 已实现 |

| `status-mysql8.bat` | 两个实例的状态与库列表 | ✅ 已实现 |

### 三条规划原则

1. **与 5.7 物理隔离、端口互斥** —— 数据目录各自独立（`D:\mysql8\data` vs `D:\mysql-5.7.32\data`），但端口同为 3306，因此**同一时刻只能有一个在跑**；5.7 服务建议改为手动启动。
2. **脚本必须幂等且可安全重复执行** —— `start` 发现 3306 已在监听时直接报 `[SKIP]` 返回成功，不重复拉起进程。
3. **口令只从 `.env` 读** —— 需要口令的脚本按行解析 `infra/.env`，用完立即 `set "DBPWD="` 清变量。
