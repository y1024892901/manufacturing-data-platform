# ingestion/loaders/ — ODS 落地逻辑

## 技术栈
Python · PostgreSQL `INSERT ... ON CONFLICT` · 分区表

## 放什么代码

| 文件 | 内容 |
|---|---|
| `ods_writer.py` | 幂等写入：按 `_row_hash` 去重，按批次管理 |
| `batch.py` | 批次生命周期：开批次 → 写入 → 校验 → 关批次 |
| `verifier.py` | 落库后校验：行数、非空率、主键唯一性 |
| `partition.py` | 大表按 `_extract_ts` 分区管理 |

## 写入语义

| 场景 | 处理 |
|---|---|
| 主键已存在且 `_row_hash` 相同 | 跳过（无变化） |
| 主键已存在但 `_row_hash` 不同 | 更新（记录变更） |
| 主键不存在 | 插入 |
| 本次批次整体失败 | 按 `_batch_id` 整批回滚，不留半截数据 |

## 干什么事情
1. 保证**幂等**：同一批数据重跑多次，结果完全一致
2. 记录每行的变更历史到 `ods_change_log`，支撑"数据血缘到行级"的演示
3. 批次校验不通过（如行数为 0）时拒绝关闭批次并告警
