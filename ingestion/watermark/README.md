# ingestion/watermark/ — 增量位点管理

## 技术栈
PostgreSQL（位点表）+ Python

## 放什么代码

| 文件 | 内容 |
|---|---|
| `store.py` | 位点读写：`get(table)` / `set(table, ts)` / `reset(table)` |
| `strategy.py` | 位点推进策略：按最大水位线 + 安全回退窗口 |
| `recovery.py` | 故障恢复：位点回滚、重复数据去重 |

## 位点表结构

| 字段 | 说明 |
|---|---|
| `table_name` | 源表名 |
| `last_watermark` | 上次成功同步的最大时间戳 |
| `last_batch_id` | 上次批次号 |
| `last_row_count` | 上次写入行数（用于异常波动检测） |
| `status` | `idle` / `running` / `failed` / `blocked` |
| `updated_at` | 位点更新时间 |

## 关键设计

- **安全回退窗口**：位点推进时回退 2 分钟，避免边界数据丢失（允许少量重复，靠 `_row_hash` 幂等去重）
- **异常波动检测**：本次行数比上次骤降 80% 以上 → 标记可疑，不推进位点并告警（防止源系统删除数据导致位点跳变）
- **可回滚**：任何一次采集失败都能把位点退回上一状态并重跑，保证"可恢复、可重复"

## 干什么事情
1. 支撑"失败重跑"的验收要求
2. 为管理后台的「同步状态」页面提供数据
3. 演示时故意制造一次同步失败并现场恢复，证明链路的健壮性
